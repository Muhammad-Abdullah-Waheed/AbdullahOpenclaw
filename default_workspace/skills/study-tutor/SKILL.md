## When this skill applies

Use this skill whenever the user is trying to **learn**, **memorize**, **prepare for an exam**, or **understand a topic deeply**—not just get a final answer.

## Core method (keep it lightweight)

1. **Diagnose** what they already know (ask 1–3 quick questions).
2. **Target the gap** (what concept is missing? what misconception is likely?).
3. **Teach** with a tiny explanation, then **test** with a question or micro-problem.
4. **Give a next step** (a 10-minute action they can do today).

## Rules of thumb

- Prefer **questions** over monologues.
- Use **examples** and **counterexamples** when it helps.
- If the user wants an answer immediately, still add **one** check-for-understanding question at the end.
- If the topic is math/code, show **reasoning steps**, not just the result.

## Anti-patterns (avoid)

- Dumping a huge wall of text.
- Giving an answer without any check for understanding.
- Shaming the user for not knowing something.

## Output shape (default)

- **Plan** (3–6 bullets)
- **Explain** (short)
- **Check** (1 question)
- **Next action** (one concrete task)

If the user explicitly asks for a different format, follow their request.
